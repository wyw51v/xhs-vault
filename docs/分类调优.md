# 分类调优

规则驱动的分类能到八成左右。这份文档是把它调到八成的过程中踩到的坑，
每一条都实际发生过，改一次要重跑一遍才发现。

## 一、顺序即优先级，具体用途要排在主题词前面

规则先匹配先得。所以「AI 工程实践」如果排在「获客与增长」前面，
一条讲**用 Agent 做社区获客**的笔记会被工程实践抢走，因为它含 `Agent`。

判断标准是**读者什么时候会回来找它**：

| 分类 | 什么时候来找 |
|---|---|
| AI 工程实践 | 我要动手配工具、写 Agent |
| AI 行业观察 | 我想知道行业在发生什么 |
| 获客与增长 | 我要找用户、做流量 |
| 认知与方法 | 关于我这个人怎么变好 |

一条笔记同时含 `Agent` 和 `Reddit`，它的用途是获客，就该归获客。
所以创业与增长那一组要排在 AI 那一组前面。

## 二、通用词有毒

这几个词看着像分类信号，实际会造成大面积误判：

| 词 | 抓错了什么 |
|---|---|
| `管理` | 「Agent **管理**界面」「时间**管理**」→ 都进了职场 |
| `团队` | 「Claude Code **团队**在用的工具」→ 进了职场 |
| `插件` | 「n8n 上千**插件**」→ 进了 Claude Code 生态 |
| `产品` `应用` `方法` | 太泛，会把整个分类变成吸收池 |

改法是换成带语境的组合：`管理` → `带团队|向上管理|管人|新人经理`。

判断一个词能不能用：**它单独出现时，能确定这条笔记属于这一类吗？**
不能就别用。

## 三、作者名会污染判断

如果把作者名拼进分类依据，会出现这种情况：

```
标题：某亿万富豪谈拖延：不是懒，是你没得选
作者：XX的开源人生            ← 含「开源」
结果：被判为 AI 工程实践
```

小红书博主名里塞主题词是常态：`XX出海圈`、`XX的AI实战`、`XX的开源人生`。

**分类只看标题。** 作者名只用于两件事：识别自己的账号，以及抽实体
（「这条跟谁有关」，作者本身就是答案之一）。

## 四、`\b` 词边界在中文旁边不成立

Python 的 `\w` 包含 CJK，所以「多Agent协作」里 `Agent` 两侧都是 `\w`，
`\bagent\b` 匹配不到。

```python
# 会漏
re.search(r'\bagent\b', '多Agent协作架构')   # None

# 换成只排除 ASCII 的 lookaround
re.search(r'(?<![a-z0-9])agent(?![a-z0-9])', '多Agent协作架构', re.I)   # 命中
```

`classify.py` 里的 `fix_wb()` 自动做这个转换，规则里照常写 `\b` 就行。

修这个 bug 之后，`Agent` 实体的命中数从 14 涨到 27。

## 五、排除模式解决「含有某词但讲的不是那件事」

规则支持第三项：

```python
("AI 工程实践",
 r"claude code|codex|agent|开源|...",     # 正模式
 r"访谈|播客|采访|对谈|收购|悟道|心态"),    # 排除模式
```

「推荐 Claude Code 创始人这篇访谈」含 `claude code`，但它是行业观察不是工程实践。
排除模式挡掉这类。

也可以靠顺序解决（把行业观察排在工程实践前面），两种手段配合用。

## 六、正文补分类的窗口要小

标题判断不了的笔记，可以用正文再判一次。但**窗口开太大会被带偏**：

一篇讲拖延的文章，正文里提了一句「开源」，用 4000 字窗口就会被判成工程实践。

实测 500 字左右合适，那部分最接近摘要。窗口从 4000 收到 500 之后，
正文补分类的准确率明显上升。

## 七、「其他」桶的占比是唯一有意义的进度指标

给每个分类加子簇之后，看落在「其他」子簇里的比例：

- 手工调过的分类：3% 左右
- 没调过的分类：40~56%

这个数字告诉你还有多少没分到位。降不下去就说明该加子簇规则了，
而不是该改分类规则。

注意区分两件事：**分类对不对**和**子簇够不够细**。
把一条笔记从错的分类挪到对的分类，它仍然会落在新分类的「其他」里。
「其他」占比不会因此下降，但分类质量提升了。

## 八、规则有天花板，剩下的靠人工覆盖

调到某个程度之后，再改规则就是在别处开新洞。这时候该停。

`data/overrides.json` 是人工覆盖，`{note_id: "分类名"}`。
读内容判断一条，写一行。**规则打底加人工纠偏**是这类任务的常见做法，
不必指望规则覆盖全部。

要更彻底就让模型逐条读全部笔记再分类。那是一次性成本，
之后新增的笔记还是走规则 + 纠偏。
